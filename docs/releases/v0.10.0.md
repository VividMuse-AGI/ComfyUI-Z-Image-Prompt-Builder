# v0.10.0

## 中文

本次聚焦 **人物卡／穿搭卡＋模块随机锁定**，节点总数仍为 11 个。

- 右键完整节点或标准模块，打开“人物卡 / 穿搭卡 / 模块锁定”。无需增加节点高度。
- 人物卡保存人物模块的 20 个字段，含身形和妆容；穿搭卡保存服装模块的 21 个字段。发型保持独立，不保证生成人脸身份一致。
- 支持保存、应用、应用并锁定、导入导出和删除；完整节点与对应独立模块互通。卡片随工作流保存，每节点最多 100 张、名称最多 80 字符、导入不超过 1 MB。同类型同名覆盖需确认，导入不会自动应用。
- 完整节点支持八模块快捷锁定，独立节点锁定自身；原字段级锁定保留。跟随预设落实为具体值，未解析随机项需先选具体值。解锁不自动随机；手动编辑、切换预设和清空仍有效。
- 应用只影响所属模块，不覆盖其他模块、自由提示词或执行历史。已连接目标输入和 TXT 替换会阻止不生效的编辑；无新增端口、后端参数、依赖或在线调用。

## English

This release adds **Person / Outfit Cards and Module Locks**, keeping the package at 11 nodes.

- Right-click the full builder or a standard module and choose **Person / Outfit Cards / Module Locks**. No additional node height.
- Person cards hold 20 person fields including physique and makeup; outfit cards hold 21 clothing fields. Hair remains independent. Fixed descriptions do not guarantee face identity.
- Save, apply, apply-and-lock, import/export and delete cards. Exchange cards between the full builder and the corresponding standalone module. Save the workflow to keep cards. Limits: 100 cards per node, 80-character names, 1 MB imports. Replacement requires confirmation; importing never applies automatically.
- Whole-module shortcuts supplement existing field locks. Follow Preset becomes a concrete value; choose concrete options for unresolved Random fields first. Unlocking does not reroll. Manual editing, preset changes and clearing remain available.
- Application changes only its module, preserving other modules, free text and execution history. Linked target inputs and TXT replacements are guarded. No new ports, backend inputs, dependencies or online services.

### Install and verify

Download **ComfyUI-Z-Image-Prompt-Builder-v0.10.0.zip**, verify **SHA256SUMS.txt**, and extract into `ComfyUI/custom_nodes`. The fixed root is `ComfyUI-Z-Image-Prompt-Builder`. Git users should back up local edits before `git pull --ff-only`. Restart ComfyUI and refresh the browser. Avoid duplicate active installations.

Coverage: 195 Python tests, 23 frontend suites, 15 JS syntax checks and three generated catalogs; representative bilingual Classic/Nodes 2.0 interactions, text-only execution and user acceptance.
