# v0.19.0

2026-11-07

## 中文

本版扩展少量有明确字段依据的动作冲突识别，并让结果面板更清楚地说明“改了什么、为什么保留”。默认组合继续保持原行为，不新增节点或候选条目。

### 更新内容

- 协调优先新增明确站姿与坐姿腿部动作、明确站姿与鸽子式伸展的冲突识别。规则只覆盖已确认的字段组合，不把一般屈膝、交叉腿或侧身都视为矛盾。
- 同一动作组先收集适用约束，再从本次原候选池筛选，最多提交一次替换。替代必须同时满足适用规则；没有可靠候选就保留原结果，不清空动作或扩展随机范围。
- 结果面板先显示实际执行模式、调整字段数量和保留／未判断原因。“查看协调详情”默认折叠，可用键盘展开，包含具体规则、前后值和候选数量；同一字段不会重复计数。
- 中英文说明同步，继续使用 14px 字号、1.6 行距和有界滚动；英文摘要按数量使用正确的单复数。

### 使用与边界

在完整节点或独立姿态／场景节点中，将需要变化的字段设为“随机抽取”，选择“协调优先”并运行，再打开“查看上次结果”。只开启协调不会自动启用随机。

当前新增站姿案例的原池可能没有可靠替代。这时会显示保留原因及候选数 0；这是准确解释冲突，不是已经自动修正。已有教室／泳池规则仍可在合适原池中调整随机姿态。

指定值、跟随预设、禁用字段、锁定内容与上游输出保持既有保护；自由提示词和 TXT 原文不改写，相关不透明上下文保守跳过。不解析自然语言、不保证图片动作正确。

### 兼容与更新

- 保持 11 个节点、既有端口与输入顺序，旧工作流缺少组合协调输入时仍使用默认组合。
- 默认流程与随机池不变。协调优先可能因规则覆盖变化影响同种子结果；跨版本需要复现时保留对应版本、输入与结果快照。本次冻结的 74 个原有案例没有输出变化，52 个新增冲突案例仅增加无候选说明。
- 卡片、收藏与结果导出格式不变。导出仍是只读内容快照，不是可执行工作流；本版没有将协调诊断块加入导出格式。
- 历史记录仅保留在当前节点运行时；刷新或节点重建后可能清空，需要长期保存的结果请先导出。

## English

This version adds a small set of explicit pose-conflict checks and makes execution results clearer about what changed and why content was retained. Standard preserves existing behavior, without new nodes or candidate entries.

### Changes

- Coherence First detects specific standing poses combined with explicit seated-leg actions or a pigeon stretch. Coverage is limited to confirmed field combinations; bent legs, crossed legs and sideways poses are not generally classified as conflicts.
- Applicable constraints for one action group are collected before screening the original candidate pool, with at most one replacement. A replacement must satisfy the applicable rules. Without a reliable candidate, the original result remains; fields are not cleared and candidate scope is not expanded.
- The result panel summarizes the executed mode, adjusted-field count and retention or skip reasons. View Coherence Details starts collapsed and supports keyboard interaction, showing rules, before/after values and candidate counts. Repeated fields are counted once.
- Bilingual explanations retain 14px text, 1.6 line height and bounded scrolling. English counts use the appropriate singular or plural form.

### Usage and limits

On the full builder or standalone Pose/Scene nodes, set the intended fields to Random, select Coherence First, run and open Last result. Enabling coherence does not enable randomization.

The original pools for newly covered standing conflicts may have no reliable replacement. A retention reason and zero eligible candidates describe that limitation, not a successfully corrected pose. The existing classroom/pool rule can still adjust a random pose when an eligible candidate is available.

Explicit values, preset-following values, disabled fields, locked content and upstream output retain their existing protection. Free prompts and TXT text stay verbatim, with conservative skipping for relevant opaque context. This is not natural-language interpretation or a guarantee of correct generated anatomy.

### Compatibility and updating

- The 11 nodes, existing ports and input order are unchanged. Legacy workflows without the coherence input still use Standard.
- The default random flow and candidate pools are unchanged. Changes to rule coverage may affect same-seed Coherence First results across versions; retain the version, inputs and result snapshot for cross-version reproduction. All 74 frozen existing cases retained their outputs; 52 newly covered conflict cases gained only no-candidate explanations.
- Card, favorite and result-export formats are unchanged. Export remains a read-only content snapshot, not an executable workflow. This release does not add the coherence diagnostic block to the export format.
- Execution history is transient node state and may clear after refresh or node reconstruction. Export important results before these actions.

Back up workflows and personal libraries, avoid duplicate installations, restart ComfyUI and refresh the page after updating. See the [README](../../README.en.md) for installation steps.
