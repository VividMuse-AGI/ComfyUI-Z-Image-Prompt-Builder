# v0.20.0 服装动作语义与结构信息设计方案

日期：2026-11-08  
修订：第二版，取代原自动协调扩展范围。  
状态：修订版阶段二最小实现及自动化回归通过，详见[阶段二验收](../testing/2026-11-08-v0.20.0-r2-phase2-acceptance.md)。两个手动动作已加入开发代码；阶段三既定界面与兼容验收完成，一键复制问题已定位为验收会话的虚拟剪贴板干扰，干净标签页中英文系统复制均通过，详见[阶段三验收](../testing/2026-11-08-v0.20.0-r2-phase3-acceptance.md)。版本号及正式安装未修改，尚未提交发布。  
基线：v0.19.0，提交 `90108ae414731b1c4f4d24e7d1df9ae047471ef1`。

## 1. 修订结论

v0.20.0 改为小范围内容语义完善，不再承诺新增服装动作自动纠错。先让用户能明确选择“翻领”或“领口边缘”，并建立少量可核查的服装结构标注，为后续协调提供依据。

保留旧“轻扶衣领”的标识、选项名称与中英文输出；新增两个词义明确的手动选项，不进入内置随机池。不静默修改旧工作流、旧卡片或已导出的内容，不改变旧输入的同种子结果。

结构标注在本版仅形成开发文档中的审查表，不加入运行时判断或公开数据格式。没有明确排除依据的属性保持未知，不为了让协调规则成立而补造“无领”“无口袋”事实。

## 2. 修订依据与范围变化

[原阶段一验收](../testing/2026-11-08-v0.20.0-phase1-acceptance.md) 已核对 198 个发布文件，完成 73 项定向回归及 328 个重复执行案例。该记录是原范围的历史结论，不是修订版验收。

已复现的输出为“穿缎面吊带长裙；一手轻扶衣领”，英文使用 collar。问题首先是动作对象不够精确，而不是已证明某类服装一定无法执行该动作。口袋方向缺少明确排除信息；完整鞋靴动作又涉及本版之外的来源和结构限制。

| 项目 | 原设计 | 修订后 |
| --- | --- | --- |
| 主要交付 | 最多两类自动协调规则 | 两个手动动作选项、使用说明及结构标注审查表 |
| 旧动作 | 不改词条 | 仍不改，不自动映射到新动作 |
| 新动作 | 不增加 | 仅新增两个精确选项，内置随机来源保持不变 |
| 结构知识 | 依靠既有字段直接判断 | 先整理小型三态证据表，不接入自动纠错 |
| 协调功能 | 扩展覆盖 | 保持 v0.19.0 的范围、权限和说明 |
| 接口 | 所有输入定义不变 | 节点与端口不变；仅手部动作下拉允许追加两个值 |
| 兼容承诺 | 默认组合保持不变 | 对全部旧输入保持不变；显式选择新动作才产生新文字 |

## 3. 内容设计

### 旧动作保持原样

保留 `pose.hand_action / adjust_collar`，显示名称仍为“一手轻扶衣领”，原中文正文和英文渲染均不变。它继续参加原有随机流程，不从池中移除、替换或降权。

说明中提示：该旧选项保留原有表达；需要明确接触对象时，手动选择下面两个选项。说明只放在字段帮助或使用文档，不向最终提示词添加“旧版”“兼容”等文字。

### 两个新增手动选项

以下为拟定内容，后续实施应在中文不同密度、英文正文和界面翻译中保持相同语义。

| 项目 | 翻领动作 | 领口动作 |
| --- | --- | --- |
| 稳定 ID | `touch_foldover_collar` | `touch_neckline_edge` |
| 中文选项与简短表达 | 一手轻扶翻领 | 一手轻扶领口边缘 |
| 中文详细正文 | 一只手轻扶衣服向外翻折的领片，另一只手自然垂落 | 一只手轻扶衣服领口的布料边缘，另一只手自然垂落 |
| 英文选项 | Hand lightly touching a fold-over collar | Hand lightly touching the neckline edge |
| 英文正文 | one hand lightly touching the folded-over collar of the garment, the other arm resting naturally at the side | one hand lightly touching the fabric edge of the neckline, the other arm resting naturally at the side |
| 对象边界 | 向外翻折的领片，不泛指立领、领口、肩带或西装驳头 | 衣服开口处的布料边缘，不要求翻领；不等于触碰皮肤或拉扯肩带 |

不把领口动作说成“任何服装都适用”。用户仍需选择包含相应结构的衣服；明确手动选择时不自动改衣服、不自动替换动作。自动判断与穿搭推荐均不在本版范围。

两个选项追加在既有手部动作选项之后，不插入旧值之间，不调整旧默认值。旧动作与新动作语义接近是有意保留的兼容选择，不合并 ID 或别名。

### 用户可见效果

完整节点和独立姿态动作节点都可手动选择新动作；支持已有复制、中文／英文输出、分段和内容快照导出。它们仍属于“手部动作”，不增加“服装结构”下拉、不增加协调开关。

用户可以沿用已有姿态卡保存新选择；本版不新增卡片类型。若现有卡片校验依赖动作白名单，应作必要的内容注册，但不改变文件结构或存储位置。

## 4. 手动选项与随机池隔离

新增值不能仅因出现在下拉列表中就进入随机来源。当前 [nodes.py](../../nodes.py) 的 `RANDOM_FIELD_OPTIONS` 从 `FIELD_OPTIONS` 复制，是需要在实施时重点审查的路径。

要求覆盖原子随机、主题／预设动作套组、跨风格池、回退池、引用扩展及前端随机按钮。显式区分“可手动选择”和“可进入内置随机”，新条目只属于前者；实现选用最小必要机制，不借机重构所有模块。

必须保持：

- 旧候选成员、顺序、重复项和权重一致；不追加带新动作的套组。
- 旧默认随机流、协调随机流的调用次序与盐值不变。
- 新动作不会被自动注入预设、主题池或已有卡片。
- 指定新动作后，即便其他字段随机，也不能因为套组缺少该动作而覆写手部字段或自动增加衣服。
- 协调优先不替换用户指定的新动作，仍执行已有规则并保持固定内容保护。

“仅手动”指不加入内置候选来源，不妨碍用户主动把新文字写入自己的 TXT 或按现有功能随机抽取其个人词库；此类用户内容仍按既有原文规则处理。

若无法隔离新增值而不影响旧随机结果，先暂停实现并说明具体差异，不能默许随机池变化，也不能靠批量更新基线掩盖问题。

## 5. 服装结构标注审查表

### 本版交付形式

在开发文档中整理最多八条已存在服装条目的证据表，不新增运行时 JSON 文件、用户字段或通用知识引擎。每条按既有字段路径及稳定选项 ID 标识，不以界面中文标签作为唯一键。

审查表记录：

- 既有条目的 ID、中文正文与英文对应内容。
- 所讨论的结构及其所在衣物部位。
- `supported` 支持、`excluded` 明确排除、`unknown` 未知三态。
- 正向证据原句、排除依据或未知原因。
- 是否只适用于某个活动服装分支，以及叠穿等解释限制。

标注是待审的开发资料，不会生成额外提示词、改变诊断状态、给词库打“模型已验证”标签，或让当前“协调优先”声称新增覆盖。

### 属性与判定边界

只讨论三个窄属性：向外翻折的领片、衣服领口布料边缘、可供手插入的衣物口袋。不能把衣服有装饰口袋等同于手部动作可用，也不能把“翻领”自动替换成“西装驳头”。

| 三态 | 标注意义 | 禁止的推断 |
| --- | --- | --- |
| 支持 | 该条目明确描述所需结构；若用途仍不明，标注用途限制 | 有口袋不自动证明口袋可伸手、位置合适或手部可见 |
| 明确排除 | 条目对同一对象明确排除结构，有可引用依据 | 不根据服装大类、图片印象或常见款式填写 |
| 未知 | 未提到、含义宽泛、双语不一致或证据不足 | 不按“默认没有”使用，不算作冲突 |

本轮允许排除态数量为零，不要求为了三态表完整而制造反例。没有排除态，就没有据此自动报冲突的依据。

初始审查对象可从现有衬衫式连衣裙、短款牛仔外套、缎面吊带长裙、挂脖连衣裙、直筒牛仔裤、工装裤与瑜伽裤中选取；这些只是审查对象，不是预先批准的属性映射。

### 与未来协调的关系

未来若要接入自动协调，必须另行评审完整的有效服装视图、未知与不透明上下文、候选来源以及单向修改权限。叠穿、不使用、隐藏分支、普通字符串断链、用户 TXT 和完整动作描述均不能由这张表自动补全。

只有明确动作需求与明确排除条件同时成立，才有资格讨论冲突；有未知项时不能凭缺失报错。没有真实原池替代的案例仍须保留，不能为配合新动作自动换衣。

本版不开展自动纠错实现，也不将新增两个手动动作作为可随机候选去制造“协调成功”的演示。

## 6. 兼容与迁移规则

本版不执行数据迁移。兼容不是把旧“轻扶衣领”猜成某个新动作，而是保留其原值和原输出。

| 对象 | 必须保持 | 明确允许的变化 |
| --- | --- | --- |
| 11 个节点 | 类名、数量、端口类型与顺序、输入名称与排列、默认值不变 | 手部动作下拉追加两个值，相关中文／英文目录同步 |
| v0.19.0 旧输入 | 默认及协调模式的中英文正文、尺寸、上下文、卡片候选及采样语义不变 | 帮助说明和文档补充 |
| 旧随机 | 候选集合、顺序、权重及同种子结果不变 | 不允许新增动作进入任何内置随机来源 |
| 显式新动作 | 其他固定字段及衣物不受改写 | 新动作输出、对应结果记录与卡片内容按选择变化 |
| 旧工作流和卡片 | 无需迁移，不重写、不重新保存用户文件 | 打开时能看见新增可选项 |
| 新动作卡片 | 使用既有字段结构存储，当前版本正常校验与应用 | 旧版本可能无法识别新值，不承诺向下兼容新内容 |
| TXT 与自由提示词 | 原文保留，不扫描、替换“衣领”等词 | 用户可以自行编写更明确的文字 |
| 内容导出与历史 | 导出格式和临时历史行为不变，已导出文字不重渲染 | 新执行结果含用户明确选中的新文字 |
| 协调诊断 | 规则 ID、状态、版本和覆盖范围不变 | 不添加服装动作已检查或已修复的虚假说明 |
| 本机数据 | 不修改个人词库、卡片、收藏或工作流 | 经后续授权后才安装发布版本 |

使用新动作的工作流或卡片应在 v0.20.0 及以后使用。回退到 v0.19.0 前，先导出所需文字并保留原文件；可在副本中改选旧版本支持的动作，不能自动把两个精确动作合并为旧动作。旧版本无法识别新值时的实际表现须在兼容说明中如实记录，不能声称旧版一定能优雅降级。

不添加迁移按钮或另一个兼容模式。生成目录中的新 ID、英文映射及卡片验证仅做必要注册，不修改旧 ID 的含义。

## 7. 范围与非目标

本版交付限于两个动作选项、它们的中英文与密度表达、手动随机隔离、使用说明和小型结构审查表。

不扩充口袋、拉链、袖口等动作；不重写其他词条；不新增规则、候选池、主题、预设、节点、端口、在线 API、外部依赖或持久化格式。已有头饰依赖、构图适配与引用池要求保持原有行为，不宣传为新增能力。

不执行生图、更新生产安装、提交或发布。本轮仅修改设计，后续实施和发布分别按用户指令进行。

## 8. 修订后的实施与验收顺序

### 阶段一修订 文案与结构资料审查

复用原阶段一的 v0.19.0 冻结基线，不重新进行大范围种子扫描。确认两个新选项的唯一 ID、中文三个密度及英文对象语义，完成最多八条结构标注，并追踪所有从手动选项派生随机候选的路径。

出口是内容表、结构证据表、随机隔离清单及允许变化清单；不再要求先找到一条自动纠错规则。如果词义仍不清楚或隔离方案无法保持旧输出，则先修订，不进入实现。

### 阶段二 最小内容实现与定向回归

按后续授权实施两个选项及必要的目录注册／随机隔离。保持旧动作内容不变，优先复用现有数据结构和校验流程，不引入无消费者的运行时结构标注系统。

重点验证：

1. 旧冻结案例逐项对比，产品旧输入的正文、尺寸、上下文与结果数据不变。旧文件清单变化需按允许修改清单核对，不能要求修改后的源码仍与旧包逐字相同。
2. 全部旧接口保持，只有预期的手部选项列表增加；三个占位值及旧选项的相对顺序不变。
3. 从所有内置候选来源检查新 ID 不可达，比较旧池顺序与权重；辅以有限种子回归，不用“没抽到”代替结构证明。
4. 完整节点与独立姿态节点在两种模式、三个密度、中英文、连续／分段输出下明确表达翻领或领口，不退回含混的旧词。
5. 指定新动作、其他字段随机时，手部及固定服装不被覆盖；有旧规则冲突时仍遵守既有权限。
6. 现有姿态卡保存／应用新动作，旧卡片不变；内容复制、导出与最终结果一致；普通文本链及英文链保持原行为。
7. 结构表中的每项证据可追溯，未知不自动补成排除，翻领／领口／驳头及口袋用途不混淆。

原审计脚本含“必须等于 v0.19.0 发布包”的前置校验，适用于基线冻结，不能直接当作实现后的回归入口。后续另建对比入口读取原冻结证据，保留原脚本和原数据不变。

### 阶段三 有限界面验收

使用独立工作流，不生图。经典界面和 Nodes 2.0、中英文各验证新选项可见、标签清晰、选择不串值；复制、导出、卡片往返、保存刷新及撤销重做各取代表案例，不重复整套组合。

检查随机按钮不会引入新选项，已有随机种子行为未变；当前选中新动作是否被随机按钮替换，沿用用户既有模块随机权限，不新增“永远锁定”的特殊含义。

发布前提供实际内容差异、兼容检查及已知限制。不再以新增协调规则数量作为验收标准；修订版测试通过前不得把旧阶段一测试统计当作新功能通过证据。

## 9. 发布与暂停条件

发布收益应表述为“新增精确的手动动作表达”，不能声称已自动解决衣领、口袋或鞋靴冲突。先确认新增表达有实际可用性，再按授权准备版本信息和发布说明。

遇到必须改旧词义、扩大随机池、增加用户结构字段、改变卡片或导出格式、产生无法解释的旧输出变化，或需要自动换衣／回写上游时，暂停相关部分并重新确认范围。

当前设计的取舍是：用明确选项改善用户控制，保留已有结果可复现性；自动协调等待足够的结构证据，不在本版勉强推进。
