# 提示词节点界面精简设计方案

日期：2026-11-08  
状态：三个阶段已实施，合并回归 38 个前端脚本和 321 个 Python 测试通过。独立环境已补验中英文经典／Nodes 2.0 代表布局、四类节点纯文本执行、清空及卡片撤销／重做；2026-11-10 用户确认复制和取消正常，界面验收完成，未安装或发布。详见[合并界面验收](../testing/2026-11-08-ui-simplification-combined-ui.md)及[第三阶段记录](../testing/2026-11-08-ui-simplification-phase3.md)。  
适用项目：ComfyUI-Z-Image-Prompt-Builder。  
基线：已发布 v0.19.0，提交 `90108ae`；同时考虑工作区内尚未发布的 v0.20.0 改动。

## 1. 目标与范围

本轮通过重新排列内容、统一入口和按需展开，减少用户生成、查看和复用提示词时需要理解的概念。保留现有专业控制，不新增“简单模式／专业模式”，不扩充词库或引入新的提示词算法。

保留完整节点、八个独立模块和两个 TXT 节点。92 个结构化字段继续按当前模块显示；既有分段、英文输出、分辨率、卡片、收藏、随机锁定及组合协调功能均保留。

优先服务三条路径：

1. 选择预设 → 调整少量内容 → Run → 查看和复制结果。
2. 只编辑需要的模块 → 补充自由提示词 → Run。
3. 导入词库或应用已保存配置 → 按需随机 → 保存或复用结果。

“已保存配置”是界面组织用语，不是新增文件格式。普通用户不必先学会卡片包、字段诊断或随机候选统计才能完成上述路径。

## 2. 当前问题与调整边界

| 当前问题 | 本轮调整 | 不做的事情 |
| --- | --- | --- |
| 结果正文位于多段说明及卡片操作之后 | 正文和复制前置，诊断折叠 | 不删除诊断数据，不改变结果内容 |
| 五个复制／导出按钮同列 | 两个常用复制按钮，低频操作收进“更多” | 不删除手动复制兜底 |
| 卡片、预设、锁定入口混合 | 统一保存内容的入口，锁定与检查单独归类 | 不把不同 JSON 格式合并成一种 |
| 随机按钮和执行种子容易混淆 | 标明启用随机与运行抽取的区别 | 不引入新随机模式，不改旧种子结果 |
| 清空文本和移除词库名称相近 | 按作用对象分组，执行前给出具体影响 | 不把移除词库变成删除已应用内容 |
| README 版本介绍多于上手引导 | 快速使用前置，历史和技术细节分流 | 不删除兼容限制和重要警告 |

主要依据：[结果面板](../../web/js/prompt_diagnostics.js)、[卡片与预设面板](../../web/js/workflow_tools.js)、[完整节点操作区](../../web/js/preset_sync.js)、[现有使用说明](../../README.md)。

## 3. 结果面板设计

### 3.1 正文优先

完整节点和八个独立模块的常驻入口统一显示“查看结果 / View Results”，不再把“随机未启用”作为入口的主要名称。随机状态仍可在面板里查询。尚未执行时入口可打开，显示“暂无执行结果，请先运行节点”，不伪造正文。

面板顺序如下：

```text
执行结果                                              关闭
执行记录选择     实际种子
历史结果提示（仅在当前设置与所选记录不同时出现）

复制中文   复制英文   更多…
中文提示词
[可选择、可滚动的完整正文]
英文提示词
[可选择、可滚动的完整正文]

▸ 保存为卡片
▸ 随机与组合说明
▸ 字段与技术详情
```

不新增正文语言切换状态；保留中英文两段，中文在前。英文界面翻译控件标签，不交换中文和英文的复制对象。正文保留换行和标点，不截断实际复制内容。

顶部只保留执行记录、实际种子和必要的历史警告。长会话说明移入技术详情；导出限制放在导出操作旁。正文前不再展示当前配置全文、候选数量表、协调过程或保存表单。

“随机与组合说明”中分清“当前设置”和“所选执行记录”，保留候选数量、变化模块、协调及构图省略说明，不混用下一次种子和历史种子。“字段与技术详情”保留完整诊断。两处默认折叠，不互相重复同一段说明。

沿用打开时的结果快照及最近五条内存记录，不新增自动刷新或持久化历史。面板注明运行后重新打开查看新结果；切换所选记录时，正文、复制、导出和保存卡片必须使用同一记录。

### 3.2 复制与导出

常驻操作只有“复制中文”“复制英文”和“更多…”。“更多”提供“导出结果 JSON”“手动复制中文”“手动复制英文”。使用单层菜单，不再弹出多级操作菜单。

复制失败时，在对应按钮附近显示错误和该语言的手动复制入口，展开只读文本区供选择复制。复制 API 成功返回只表述“已发送复制请求”，不声称已核对系统剪贴板内容；提示短暂显示，不长期占据面板。

手动入口始终可通过“更多”找到，以处理 API 成功但系统粘贴不符的情况。不得为了验证复制而自动读取系统剪贴板，也不依赖额外剪贴板权限。

结果导出仍是只读 JSON 快照，不是可导入的卡片或工作流。名称调整不改变导出 schema、种子字符串、正文或来源字段。

### 3.3 从结果保存卡片

“保存为卡片”默认折叠，仅展示节点实际支持的类型。展开后明确写出“保存所选执行结果”，使用历史解析字段，不读取当前编辑器值，不重新随机、不自动应用或锁定。

保留人物、发型、穿搭、姿态动作和拍摄方案已有边界。TXT 节点不增加从文本反推结构化卡片功能。

### 3.4 两类 TXT 节点

TXT 面板统一为正文优先、解释折叠的布局，但入口保留明确的“查看抽取结果 / View Draw Result”。复制按钮使用“复制抽中正文”，导出使用“导出抽取记录”。

不把抽中条目称为最终组合提示词，不把前置文本加入原导出，不新增自动翻译；手动选择模式下记录的可用性沿用现有行为，不伪造新的历史记录。

## 4. 保存内容与高级设置入口

### 4.1 统一入口但保留类型

把现有两条混合职责的右键入口重新组织为：

- “我的预设与卡片 / My Presets & Cards”：保存内容的管理和应用。
- “随机设置与检查 / Random Settings & Checks”：模块锁定、字段锁定和组合检查。

两处都不新增节点常驻按钮，不增加节点高度。README 明确入口在节点右键菜单。只替换前端菜单显示，不改序列化字段名或存储键。

“我的预设与卡片”在同一个对话框内使用三个页签：

| 页签 | 内容 | 行为边界 |
| --- | --- | --- |
| 整套预设 | 既有用户预设列表及保存、应用、导入、导出 | 沿用既有用户预设保存范围，不扩充为整份工作流 |
| 模块卡片 | 人物、发型、穿搭、姿态动作及拍摄方案类型筛选 | 拍摄方案仍是场景、摄影、视觉表现的组合，不新增通用卡片类型 |
| 组合应用 | 既有卡片快捷组合 | 保留预览和确认，未选模块保持原样；不新增“组合模板”文件 |

独立节点只呈现自己支持的功能；不显示无法应用的组合页签。类型选择、搜索、收藏和排序只过滤视图，不修改卡片内容或应用到节点。

高频操作为选择和应用；导入、导出、重命名、删除等低频管理进入“管理…”单层菜单。卡片类型和覆盖范围始终可见，不用一个笼统的“模板”名称遮蔽差别。

预览、导入预览和覆盖确认在同一面板中切换视图，提供返回；避免打开新的管理弹窗叠在原弹窗上。必要确认仍保留，不因减少点击而跳过覆盖审核。

### 4.2 锁定与检查

“随机设置与检查”先显示模块级锁定摘要；需要细调时展开字段级控制。模块部分锁定应显示“部分锁定”，不误显示为全部锁定或未锁定。

统一说明：锁定保护哪些随机操作，沿用当前实现；不把它说成禁止一切修改。手动编辑、应用预设或卡片、显式清空等已有权限不改变。解锁不自动将固定值变成随机。

锁定预设引用时的具体化、输入连线／TXT 替代的限制及解锁行为继续沿用；界面重组不得新增静默转换。高级字段选择仍需显式保存，打开、切换页签、展开说明都不写节点状态。

“检查当前组合”为独立只读操作，结果仍限定为已知规则，不声称图像质量或全局逻辑得到验证。

## 5. 随机与清空操作

### 5.1 随机名称不承诺立即生成

现有“生成随机组合”调用的是随机配置准备逻辑，最终正文由 Run 得到。因此完整节点拟显示“设置随机组合 / Set Up Random Combination”；独立模块显示“设置本模块随机 / Set Up Module Randomness”。

紧邻操作的帮助文字说明：“按随机范围准备字段；运行节点后查看结果。仅改变种子不会把固定内容变为随机。”不使用“立即换一张”“保证不同”等表述。

随机范围、种子及宿主生成后种子控制保持原位置和语义；不增加“每次运行随机”的新开关。随机按钮原有字段启用范围、锁定保护、候选来源及副作用均保留。名称本地化必须覆盖经典与 Nodes 2.0。

### 5.2 清空按对象组织

完整节点保留“仅启用当前模块”和“清空自由提示词”的就近入口。把“清空结构化模块”“全部清空”收进同一个“清空内容…”入口，选择后展示影响范围，再确认执行。

独立模块本来只有一个清空操作，不为了统一外观再套一层菜单。TXT 面板就近保留移除词库入口，不把所有清空集中到远离对象的全局面板。

| 显示名称 | 清除对象 | 明确保留 |
| --- | --- | --- |
| 清空自由提示词 | 手写／添加的自由提示词 | 结构化内容、已导入词库 |
| 清空结构化内容 | 内置字段及已应用用户模块 | 自由提示词、已导入词库 |
| 清空全部提示词 | 自由提示词及结构化内容 | 已导入词库、现有规则保留的尺寸设置等非正文状态 |
| 清空当前用户模块文本 | 所选用户模块的已应用文本 | 内置字段、其他模块、词库条目 |
| 移除 TXT 用户词库 | 已导入的完整提示词条目列表 | 已写入的自由提示词 |
| 移除 TXT 模块词库 | 已导入的模块条目列表 | 已应用的模块文本 |

以上是显示文案，不是新的清除实现。未列出的状态仍按原函数处理，不扩大删除范围。两个 TXT 节点的前置输入文本不能被本节点清空。

“仅启用当前模块”不仅切换显示：会清除其他模块的参与内容。帮助及存在其他模块内容时的确认必须明确这一点，并列出实际目标模块；不能用“切换模块”代称。自由提示词及导入库保持原行为。

打开菜单、取消确认都不修改字段。执行保持既有事务边界；已支持撤销的路径不能丢失撤销能力，不把本次 UI 整理扩大为全系统新增撤销功能。

## 6. README 与帮助

中英文 README 使用一致的信息层级：

1. 节点用途、代表界面、安装。
2. 最短使用流程：选择预设，连接文本输出，运行，查看结果。
3. 完整节点与独立模块如何选择。
4. 常见任务入口表：自由输入、TXT 导入、随机、卡片、清空。
5. 输出与兼容的重要限制、进阶文档链接。
6. 开发、许可证和更新日志链接。

首页不继续累加历次版本的长介绍；历史内容移入既有更新日志或对应功能文档，并保留有效链接。随机不保证不同、TXT 不自动翻译、导出快照不能导入执行等限制放在相关操作附近，不藏到文档末尾。

中英文按钮名称与实际 UI 一致；不把界面翻译误写为任意用户文本翻译能力。不修改现有提示词正文以迎合新的 UI 名称。

## 7. 兼容与实现约束

- 节点类标识、分类、端口类型及顺序、后端输入名、默认值和旧枚举值不变。显示名称通过现有前端本地化／标签层处理。
- 保持 widgets 序列化索引和旧工作流恢复；不能为了隐藏按钮误删序列化输入。临时 UI 控件不写入提示词或持久化属性。
- 旧输入的中英文正文、分段、尺寸、随机池、候选顺序和同种子结果不变；打开面板不消费随机种子。
- 不改卡片、预设、收藏、卡片包和结果 JSON 的 schema、容量限制或存储键；导入与应用分离，覆盖确认、错误拒绝和来源说明保留。
- 当前配置、历史实际结果、下一次种子保持分离；过期预览仍需重新确认，不因统一入口跳过原有状态校验。
- 经典与 Nodes 2.0 使用同一套动作语义；优先复用已有弹窗和 widget 适配，不以隐藏占位控件制造节点长空白。
- 关闭、Esc、中文输入法确认及焦点返回保持可用；面板内复制和快捷键不误操作底层画布。字号不小于现有可读设置，长英文按钮允许换行。
- 菜单／页签仅是展示状态，默认不新增工作流持久化字段。节点移除、重配置或工作流切换后，不允许遗留弹窗写回另一节点。
- 不读取系统剪贴板做成功判定；后续正常验收标签页不调用会虚拟化剪贴板的浏览器工具接口。

主要修改范围预计为 `web/js/prompt_diagnostics.js`、`web/js/workflow_tools.js`、完整及独立节点前端适配、TXT 前端面板、翻译源和相关文档／定向测试。生成目录按既有生成流程更新，不手工修改生成文件代替源数据。

## 8. 实施顺序与验收边界

以下为分阶段验收约束，完成情况以对应验收记录为准。先做最小改动，避免另建一套界面框架。

| 顺序 | 交付 | 必要验收 |
| --- | --- | --- |
| 一 | 结果正文前置、两个复制按钮、更多菜单、诊断折叠、TXT 对应布局 | 切换历史后复制／导出／保存对象一致；空记录、复制失败、手动兜底可用 |
| 二 | 保存内容统一入口、锁定与检查归类 | 原导入导出、预览、覆盖、取消、错误拒绝、已支持撤销／重做不回退 |
| 三 | 随机文案、清空分组、双语帮助与 README | 仅改显示不改运行；确认／取消范围正确；旧工作流和固定种子样例保持一致 |

每步只运行受影响的自动化用例并补缺失断言；最终一次覆盖完整节点、一个代表独立模块和两类 TXT 的纯文本联调。中英文、经典／Nodes 2.0 的共用面板做代表性布局及交互检查，不对每个字段重复四套人工验收。

纯 UI 变化不要求生图。复制正常链路用干净浏览器会话检查；如果工具不能可靠验证系统剪贴板，只留一次明确的人工粘贴验收，不反复改产品去适配测试工具。

完成标准：

- 在约 900 CSS 像素高的桌面视口，结果面板初次打开无需滚过诊断即可看到中文正文起始与复制按钮；小视口仍可滚动访问全部功能。
- 结果主操作行只有两种复制及“更多”；全部原有导出、手动复制、诊断、保存能力仍可到达。
- 原两条混合管理入口改为两条职责清晰的入口，不新增常驻管理按钮或强制模式开关。
- 清空与移除词库使用不同文案，取消操作不改变数据；随机名称不暗示立即执行或保证变化。
- 旧数据可恢复，受影响的输出样例无非预期变化，英文界面及 Nodes 2.0 无遮挡或异常拉长。

## 9. 版本安排与暂缓事项

本方案不自动并入尚未发布的 v0.20.0，也不提前指定下一版本号。现有 v0.20.0 内容与验收记录保留；实施和发布时再明确合并范围，不能用既有内容验收替代新 UI 验收。

本轮暂缓：新词库、全新卡片格式、自动翻译服务、自动应用推荐、节点类型合并、随机算法重写、全量状态迁移及新持久化历史。

下一步整理候选提交范围、执行干净副本检查，再确认版本及发布范围；不重复运行生图测试，不自动安装或发布。
