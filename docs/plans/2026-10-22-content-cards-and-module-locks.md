# 人物卡／穿搭卡与模块随机锁定

状态：基线 v0.9.0；开发与代表界面检查完成，用户于 2026-10-22 确认人工审核无问题，并授权按顺序发布 v0.10.0、备份更新正式安装。下文保留各阶段的检查范围与限制；最终记录见 [v0.10.0 验收](../testing/2026-10-22-v0.10.0-acceptance.md)。

## 范围与约定

- 复用既有字段锁定，不新增节点、后端输入或依赖。
- 人物卡仅含人物模块的 20 个字段（含身形、妆容）；穿搭卡仅含服装模块的 21 个字段。发型独立控制，不隐式纳入人物卡。
- 完整节点与对应独立模块之间可用同一 JSON 卡片互通；其他独立模块不接受不属于自身的卡片。
- 保存卡片将“跟随预设”转换为具体字段值；“不使用”保留。尚未解析的“随机抽取”拒绝保存或锁定，提示先选择具体值，不猜测当前种子对应结果。
- 卡片存于当前节点 properties，随工作流保存；JSON 可导入、导出和删除。每节点最多 100 张，名称 1–80 字符，导入上限 1 MB；同类型同名覆盖需确认。导入仅入库，不自动应用。
- 应用只修改所属模块，不修改预设、种子、当前编辑模块、自由提示词、TXT 正文、分辨率、构图开关、排版或其他模块。提供“应用并锁定”；普通应用保留已有锁定状态。
- 涉及已连接输入或非空 TXT 替换时，拒绝捕获／应用／新增锁定，解释冲突；不静默编辑被遮蔽的控件值。
- 完整节点可对八个标准模块快捷锁定／解锁；独立节点仅限自身模块。保留原字段级精细锁定。锁定把预设引用落实为具体值，随机按钮跳过锁定字段，Run 改种子不改变这些具体值。
- 锁定不是只读权限：手动编辑、切换预设和明确清空仍按现有行为工作。解锁不自动打开随机，也不还原预设引用。
- 使用现有右键面板，不增加节点高度。中英文同时提供；键盘事件不穿透画布，Esc 在中文输入法组合期间不关闭。
- 描述复用不保证生成同一张脸。卡片不是身份 LoRA，也不包括参考图片。

## 实施顺序

1. 卡片协议、全量校验与限定模块事务；共享既有字段分组。
2. 模块锁定快捷操作与输入来源保护；不重写随机算法。
3. 紧凑管理面板、双语提示、导入导出。
4. 单元／实际 schema 回归、旧工作流与原随机回归、文档更新。
5. 独立测试界面验收，提交人工审核卡片范围、操作流和兼容性；再讨论发布。

## 必要测试

- 保存、JSON 往返、完整节点与人物／服装独立节点互通；隐藏字段和“不使用”保留。
- 错类型、缺字段、未知字段、无效选项、分类不匹配、随机值、超限及无关节点：失败时零修改。
- 应用仅覆盖目标字段；不调用全节点 onConfigure，不清空执行历史，也不重置其他模块。
- TXT 替换、输入连接阻断；模块解锁不影响其他模块锁定。
- 锁定跟随预设的字段后，更改种子及随机按钮均保留具体值；保留字段锁定兼容。
- 中英文／Classic／Nodes 2.0 的代表操作、保存重开、JSON 下载／导入与 Esc／输入法隔离。
- 无需生图；自动化通过与真实界面通过分别记录。

## 2026-10-22 实施与验收记录

- 已实现模块限定卡片捕获、具体值校验、保存／覆盖、应用、应用并锁定、JSON 导入／导出、删除及八模块快捷锁定。
- 共用既有模块分组与字段锁定属性。卡片使用独立版本化协议；不改变 Python schema、端口或默认随机行为。
- 为卡片提供仅刷新人物／服装依赖的钩子，避免调用全节点配置回调时清空历史或更改其他模块。
- 保存、应用、锁定对已连接目标输入和 TXT 替换实施保护；非法卡片在修改前拒绝。导入关闭后的异步结果不再写回节点。
- 测试真实 Python schema 下完整节点与对应独立节点互通；全部内置预设均可捕获；100 张边界、数据类型、未知字段、缺失字段、族裔分类、未解析随机值、存储快照隔离及其他模块保留通过。
- 实际 Python 解析验证：固定的人物与穿搭字段在三个不同种子下保持原值，两个独立模块的中英文输出保持一致。
- 最终公开范围干净副本：195 项 Python、23 组前端回归、15 份 JS 语法、3 份生成目录一致性全部通过。新增前端用例还覆盖模拟 DOM 下的 Esc／输入法组合、1 MB 导入上限、关闭后导入失效。开发目录额外的私有测试不计入公开数量。
- 隔离 ComfyUI 实机：Nodes 2.0 中文保存人物卡与穿搭卡、应用并锁定显示 20/20 和 21/21；英文菜单、字段及值翻译正常。Classic 英文通过现有“更多选项”入口打开面板，解锁、重新锁定和 Esc 关闭通过。
- 浏览器触发一次纯文本执行，输出保留原自由提示词和固定人物／服装。保存的独立测试工作流实际包含两张卡和 41 个锁定字段。尚未把保存文件校验冒充整页刷新验收。
- 最后将默认面板范围改为优先人物／服装（非卡片模块不再默认隐藏卡片区域），并对失效卡片预览增加错误提示；最终自动回归通过。
- 新标签页加载最终脚本并重新打开已保存测试工作流后，人物卡与 20/20 锁定显示正常；节点当前编辑模块仍为画面基础，但卡片面板默认显示人物页，执行历史为空。该项为保存后的新页面重开，不涉及丢弃其他未保存标签页。

### 人工审核项目（用户已确认通过）

1. 是否认可人物卡包含妆容、身形但不含发型的边界，以及右键入口的便利性。
2. 用常用浏览器实际导出一张卡片，并导入另一工作流／对应独立模块，确认下载落盘与文件选择交互；JSON 往返与范围校验已有自动测试，但未把它等同于真实下载验收。
3. 使用实体中文输入法编辑卡片名，确认候选字与 Esc 正常；模拟事件通过不能替代实体输入法体验。
