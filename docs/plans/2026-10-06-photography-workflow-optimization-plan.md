# 写真提示词节点后续优化方案

日期：2026-10-06

状态：首批 A1、A2 已实现；补充审核后的结果归属与保存字段错位已修复，干净运行副本及同页正常刷新通过，剩余界面／版本／压力验收待闭环。尚未提交或发布，其余项目待实施。详见[后续测试方案](2026-10-06-progress-review-and-follow-up-test-plan.md)与[首批验收记录](../testing/2026-10-06-random-diagnostics-acceptance.md)。

项目基线：v0.6.1，提交 `a3b5140373c13fa844852c78e48379e21d057935`。

参考项目：ComfyUI-Photoshoot 2.6.0，审阅提交 `84f168d65a432c96b491858af0bf7d90dde807d7`。

## 1. 产品目标

让用户能够清楚地选择内容、理解随机结果，并用同一套人物与穿搭设定规划整组写真。优先改进随机操作、构图适配和内容复用，再增加拍摄计划与可视化选片。

方案最初仅作为实施计划；2026-10-06 按用户指令开始首批测试与修复。开发、安装和发布分别记录实际进度，后续版本号在确定发布范围后再决定。

“做得更好”的验收依据是操作是否明确、输出是否符合组合逻辑、结果能否复现、旧工作流能否继续使用。提示词逻辑验收与模型生成效果分开记录；当前默认采用纯文本与界面验收，不自动执行生图。

## 2. 当前基础与需要补齐的能力

当前已有完整生成器、八个独立模块和两个 TXT 词库节点，共 11 个节点；具备 92 个结构化字段、中英文输出、三档密度、兼容随机池、用户预设、随机锁定、组合检查、模块分段和分辨率计算。

| 方向 | 当前基础 | 本方案新增价值 |
|---|---|---|
| 随机操作 | 字段设为“随机抽取”后，后端按种子解析 | 明示随机是否启用、哪些字段参与、本次实际改变了什么 |
| 内容选择 | 分类下拉、TXT 模块替换、用户预设 | 搜索与收藏、最近使用、字段级扩展条目、可选示意图 |
| 景别适配 | 精简／标准模式在近景省略内置鞋袜 | 统一处理人物、服装、动作、表情中不适合当前画面的描述 |
| 内容复用 | 保存整节点状态，支持 JSON 导入导出 | 人物卡与穿搭卡独立保存、组合和共享 |
| 成套拍摄 | 每次生成一套提示词，可通过种子重复运行 | 先规划镜头清单，明确各张差异，再逐张输出与复现 |
| 结果管理 | 接入其他文本／图像输出节点 | 后续增加计划关联、缩略图、收藏与单张重拍 |

2026-10-02 的实机核对已确认：种子变化但没有字段启用随机时，输出保持不变；启用随机字段后，输出能够变化。第一阶段要修复的是交互含义不清，保留“指定值固定、跟随预设固定、不使用即省略”的现有语义。

## 3. 实施顺序

| 阶段 | 工作项 | 可交付成果 | 前置条件 |
|---|---|---|---|
| A 易用性 | A1 随机状态；A2 执行结果与变化说明；A3 搜索收藏 | 用户能看懂当前设置和实际输出 | 当前 v0.6.1 |
| B 构图与表达 | B1 景别适配；B2 组合诊断；B3 表情扩充 | 输出的信息与镜头意图相符 | A2 的诊断展示 |
| C 拍摄计划 | C1 内容卡；C2 字段级内容包；C3 系列规划 | 保存人物与穿搭，生成可编辑的整组提示词 | A、B 的公共解析与渲染能力 |
| D 可视化与执行 | D1 素材示意图；D2 批量执行与选片 | 可看、可选、可重拍的系列工作流 | C3 稳定后再实施 |

每个工作项先做范围内的实现与回归，再进入下一项。A1、A2 构成首批交付，不把后面阶段的功能一起塞入首批版本。

## 4. 阶段 A 随机操作与内容选择

### A1 明确随机是否生效

在完整节点和八个独立模块中增加紧凑的随机状态摘要，详细信息在弹出面板中展示。

| 状态 | 建议显示 | 行为 |
|---|---|---|
| 没有随机字段 | 随机未启用，改变种子不会改变结构化内容 | 提供现有随机按钮入口和简短说明 |
| 已设置随机字段 | 已启用随机：N 个字段，待运行 | 可展开查看模块、字段与固定项 |
| 已完成执行 | 上次执行：种子 X，变化 N 个模块 | 查看该次实际输出与对比 |
| 执行后又改了选项 | 设置已修改，上次结果仅供参考 | 不把历史结果显示成当前预览 |

N 个“已设置随机字段”不等于 N 个字段都会进入最终输出。被穿搭分支、构图适配或用户模块替代遮蔽的字段，在执行结果里另行说明。

现有“生成随机组合”继续负责将范围内的字段切到随机状态；“随机范围”控制该按钮启用的字段，也影响已随机字段的候选池。Run 根据已提交的字段状态执行，不隐式启用随机，不重新打开被清空的模块。随机按钮的既有锁定规则和“仅启用当前模块”限制继续生效。

测试修正：原方案“随机范围仅用于按钮”的概括不完整；现有 `resolve_fields` 会将该参数传给候选筛选。首批保留该行为并修正文案，不改变随机流。

TXT 两个独立节点继续使用“手动选择／随机抽取”；完整节点中的 TXT 面板继续表示已经应用的文本。摘要应说明用户模块正在替代内置模块，避免用户以为内置字段随机会改变替代文本。

### A2 展示实际执行与变化原因

为完整节点和独立模块增加只读结果面板，复用两个 TXT 节点已有的执行结果展示经验。

- 显示本次提交时的种子、中文和英文输出、各模块采用的字段及相对上次可比较执行的变化。
- 结果来自后端实际执行或缓存重放。控件生成后变化的种子属于下一次执行，不覆盖本次种子记录。
- 诊断信息通过执行 UI 元数据返回，不混入提示词，不增加或重排既有输出端口。
- 没有变化时，区分“没有随机项”“候选受约束”“用户文本替代”“内容未进入输出”和“本次抽取结果相同”。仅报告引擎实际掌握的原因，不能仅凭重复结果断言候选池只有一条。
- 没有上次结果、改变了比较范围或记录不完整时，显示首次结果／不可比较，不编造差异。
- 后端一次解析供中文、英文和诊断共用，不能为了计算诊断再次消耗随机数、改变既有抽取结果。
- 展示执行中的候选数量时，注明它针对单字段还是完整组合；受联动约束的总组合数无法精确计算时，不显示虚构总数。

结果面板不回写用户输入。连续排队时按执行标识关联结果，较早任务的完成消息不能覆盖较新任务的记录；缓存结果也必须能正确显示。历史诊断按数量设上限，不无限扩大工作流文件。

### A3 搜索收藏与最近使用

在弹出的素材选择面板中支持中文名、英文名、同义词与实际短语搜索，保留原有分类。收藏和最近使用作为用户快捷入口，不改变默认随机池。

第一版先做文字检索和收藏。无图片时仍显示名称、短语和适用说明。选中内容沿用现有字段保存值，不因为界面语言变化而改变 API 值。

收藏按用户偏好保存，可导出；选中的内容仍由工作流保存。浏览器存储不可用时，正常选择和执行不受影响。节点内只保留紧凑入口，不增加长列表常驻高度。

### 阶段 A 验收

- 固定字段、跟随预设、随机字段、不使用及用户模块替代五种状态解释准确。
- 相同输入和种子仍得到相同输出；新增诊断不改变基线随机结果。
- 种子自动递增／随机化、连续队列、缓存重放和保存重开后，执行结果与实际提交一致。
- 明确锁定字段、自由文本和未启用模块不被随机按钮误改。
- 中文／英文界面和经典／Nodes 2.0 四种组合均可操作，弹层不被节点边界裁切。

## 5. 阶段 B 景别适配与摄影表达

### B1 将构图适配与提示词密度分开

增加可选的“构图适配”设置：沿用当前规则／自动适配。密度控制描述详略，构图适配控制哪些内置描述适合当前镜头；两者独立。

旧工作流和未提供此参数的 API 请求沿用当前规则。新建节点可显式保存自动适配选项，但不能仅依赖控件默认值推断新旧工作流。

| 构图 | 优先保留 | 适合减少或省略的内置信息 |
|---|---|---|
| 环境远景 | 人物轮廓、主要服装、姿态、环境关系 | 细碎眼妆、睫毛、唇面等细节 |
| 全身 | 身形、穿搭、完整动作与空间关系 | 过多面部微细节 |
| 半身／胸部以上 | 上身服装、手部、表情和视线 | 画面外的鞋袜、裤腿及不相关腿部动作 |
| 面部特写 | 脸部、头发、妆容、表情 | 下装、鞋履、全身姿态细节 |
| 手部／产品特写 | 产品、手部位置、持握方式、材质与光线 | 无关的面部和全身描述 |

以上是拟实现的描述规则，不是对 Z-Image 生图结果的保证。手部是否入镜等需要结合构图、焦点和动作判断，不能仅按一个景别标签机械删除。

保存的完整设定不变，输出时建立独立的有效字段视图。中英文、模块分段和诊断共用这一视图，显示省略原因。自动适配开启时，详细密度也受可见性规则约束；切回沿用当前规则可恢复原来的详细描述。

用户自由文本与 TXT 替代片段默认原样保留，不自动切句、翻译或删词；诊断注明该片段未参与字段级适配。

### B1 的模块串联边界

当前独立模块逐段输出文本，`PromptChainText` 另外携带运行期结构化上下文。摄影节点位于链尾时，前面的模块已经生成文本，不能假设链尾能安全地倒推和重写这些描述。

首版适配范围：完整节点，以及已获得明确上游摄影上下文的独立模块。独立模块没有明确景别时，不能因其隐含预设景别而删除用户内容。

任意顺序的全链重组留给 C 阶段的结构化拍摄配方和统一渲染入口。普通 STRING 中转可能丢失运行期附加属性，因此持久化、API 和跨节点传输不能仅依赖字符串子类。

### B2 从字段冲突扩展到摄影关系

复用当前组合检查，逐步加入：背向镜头与正面五官特写、景别与空间距离、支撑动作与支撑物、持握物与手部动作、场景与布光，以及表情内部的矛盾。

随机生成时用约束筛选候选；手动指定的矛盾组合给出说明，不擅自更改设定。无兼容候选时明确说明省略或保留固定值的原因，不借机重新启用空模块。

### B3 扩充可见的表情表达

先盘点现有表情和视线，再按愉悦、沉静、自信、惊讶、紧张等可区分方向补足缺项。用眉眼、嘴部和头部的具体变化描述情绪；第一批仅采用“轻微／明显”等简单强度，不增加未经验证的精确百分比。

每条新内容提供中文、英文、适用景别和冲突标签。完整动作与表情可以作为套组，但手动原子字段仍可编辑。以具体可见描述为主，不直接把专业面部动作编码或抽象情绪词堆入输出。

### 阶段 B 验收

- 同一人物在全身、半身、面部和局部特写下，输出范围符合规则；切换景别不丢失原设置。
- 中英文有效信息对齐，空模块和用户文本处理一致。
- 自动适配关闭时保持兼容；独立模块缺少摄影上下文时不误删内容。
- 矛盾测试覆盖手动锁定、随机字段、空候选、TXT 替代及背向人物。
- 记录可见性与冲突原因；文本测试通过不能标记为模型生图验证通过。

## 6. 阶段 C 可复用内容与拍摄计划

### C1 人物卡与穿搭卡

人物卡保存人物与可选发型字段；穿搭卡保存服装、颜色、材质、图案、配件等完整穿搭。应用卡片只更新所声明的模块，不附带修改画幅、种子、场景和自由文本。

保留整节点用户预设，抽取其验证与导入导出能力供卡片复用。第一版以工作流内保存和 JSON 导入导出实现跨工作流复用，暂不依赖服务器任意路径读写。

卡片须包含稳定标识、名称、结构版本和字段值。穿搭替换完整声明其管理的分支，防止上一套连衣裙与新套装裤装残留叠加。人物卡表示描述一致性，不承诺人脸身份锁定；角色 LoRA 或参考图的辅助能力另外设计。

### C2 字段级内容包

现有 TXT 模块库提供整段替代，新增内容包提供单个字段选项，两者并存。内容包第一版使用版本化 JSON。

| 属性 | 用途 |
|---|---|
| 稳定 ID 与字段归属 | 识别选项，避免改显示名称导致工作流失效 |
| 中文／英文名称与短语 | 分离界面标签和实际输出 |
| 搜索标签与同义词 | 支持搜索与分类 |
| 适用／冲突标签 | 约束景别、场景、动作和穿搭 |
| 是否加入随机池 | 默认关闭，由用户明确启用 |
| 内容版本与来源 | 支持复现、去重和来源记录 |
| 可选示意图引用 | 为 D 阶段预留，无图条目照常使用 |

沿用已有中文保存值作为旧数据入口，新 ID 通过映射逐步接入，不在第一批全面改名。内置内容包与用户内容分层，重名不可静默覆盖内置项。

导入时校验版本、大小、条数、字段归属、重复 ID、文本类型和约束引用；具体上限随首版样例和性能测试确定。缺少英文的用户条目不调用在线翻译，明确标记原文保留。共享工作流嵌入实际使用条目的快照，避免接收方缺失本地内容包；源包改变时需显式更新快照。

同名但描述不同、同义而表达重复的条目应提示人工选择，不只按标题去重。不允许导入可执行表达式。

### C3 先生成计划，再输出提示词

新增独立的拍摄计划入口，不增加完整节点的常驻高度。第一版输出可审阅的镜头清单与可选择的单张提示词，批量执行放在 D 阶段。

建议首版采用一个“写真拍摄计划”节点：输入明确的结构化配方和系列参数，按“照片编号”输出该张中文、英文、宽度、高度及可选采样种子，并提供计划数据。旧节点输出端口不变；需要输出配方的旧节点仅在末尾追加可选能力，并做迁移回归。

配方承载原始选择、锁定项、解析字段、用户替代片段、渲染设置和内容版本；不能从任意自然语言提示词反向猜测这些信息。核心规划和渲染作为后端纯函数，前端预览调用同一实现，不维护另一套随机算法。

以“两套服装，每套六张”为首个验收例子：人物、发型、场景和主光固定，每套服装安排两张全身、两张半身和两张特写，逐张改变兼容动作与表情。用户可修改单张、重新规划未锁定的镜头，或只导出整组文本。

规划要求：

1. 明确固定模块、可变化模块、目标张数、景别覆盖与服装轮换方式。
2. 将照片编号、提示词组合种子和生图采样种子区分显示。不能承诺数值相距更远的种子必然带来更大图像差异。
3. 根据兼容候选生成计划，以最终有效结构化组合及输出文本检查重复；两套不同原子选择若渲染为相同提示词，也计为重复。
4. 候选不足时返回已生成数量与原因，允许用户选择接受重复或调整范围。不采用无限重抽，不虚构可用组合总量。
5. 先覆盖各套服装的目标景别，再分配动作和表情；短系列也要能解释哪些覆盖目标无法满足。
6. 固化计划后追加照片，不改变已有编号和内容；重新规划是显式操作。不要仅靠依赖总张数的公式重算所有照片。
7. 保存规则版本、内容快照和每张的最终解析结果；精确重放读取快照，升级词库后的重新规划另存新版本。

### 阶段 C 验收

- 人物卡与穿搭卡能独立应用；空值、互斥分支、重名及旧工作流有明确处理。
- 相同配方快照、规划版本和种子生成同一计划；预览与实际输出一致。
- 示例计划满足两套服装分别覆盖三种景别；可行时不重复，不可行时明确说明。
- 单张锁定、追加计划、换语言和导入导出不改变已固定的镜头。
- 无前端的 API 请求可以生成或重放计划；普通字符串丢失附加属性不会被误判为完整配方。

## 7. 阶段 D 素材预览与系列执行

### D1 渐进增加素材示意图

先覆盖容易混淆的服装、鞋履、发型和头饰，再考虑姿态、布光。服装以统一人体模型或平铺形式展示，动作可采用示意图；示意图用于解释选项，不表示用户当前模型的实际输出。

图片使用明确来源的本地静态资源或用户主动选择的本地图片，按需加载并提供无图回退。缺图、资源体积和离线使用纳入验收，不因图片预览而阻塞文字选择。

新增图片需要单独制作与验收记录；不能把本方案视为已经授权启动批量生图。

### D2 批量执行与选片

在计划稳定后，提供明确的“执行这组计划”操作。提交前显示镜头数量、尺寸及固定／变化项；任务与计划编号绑定，支持查看进度和停止继续提交。

先做逐张受控提交，不修改用户的通用队列逻辑。取消只影响本次系列仍待提交的镜头；如需取消已排队任务，只针对本次系列可识别的任务，不清空全局队列。

区分两个重拍操作：

- 保持镜头重拍：保留最终提示词和尺寸，改变采样种子。
- 重新规划此张：只更改该张允许变化的字段，其余镜头不变。

图像缩略图来自实际执行结果，不用规划预览冒充。保存照片编号、实际提示词、采样种子、尺寸和重拍次数；出错后可恢复尚未完成的镜头，防止重新提交已成功的任务。

### 阶段 D 验收

- 选择预览、收藏和图片回退在中文／英文、经典／Nodes 2.0 中正常显示。
- 队列提交前的计划和实际请求一致；单张失败、用户停止、重新连接不会引发整组重复提交。
- 重拍照片与其原始计划关联正确，不影响其他工作流任务。
- 调度逻辑可以用纯文本测试图验证；实际图片选片效果另列可选验收，不以模拟执行冒充生图验收。

## 8. 技术实现边界

### 8.1 复用现有实现

| 当前文件／入口 | 后续职责 |
|---|---|
| `nodes.py` 的 `resolve_fields` | 保持字段解析入口，逐步提供不改变随机结果的诊断记录 |
| `compose_prompt_text`、`render_english_module_fragment` | 接收统一有效字段视图，保证中英文语义对齐 |
| `_visible_clothing_fields` | 作为构图适配的现有规则入口，避免两处重复裁剪 |
| `modular_nodes.py` | 保持字符串串联与旁路，增加明确上下文／配方能力时做兼容适配 |
| `web/js/preset_sync.js`、`web/js/modular_nodes.js` | 显示随机状态，接入紧凑结果入口 |
| `web/js/workflow_tools.js` | 复用用户预设、锁定和组合检查 |
| `web/js/txt_selection.js` | 参考执行结果展示、缓存重放及实际种子处理方式 |
| `scripts/generate_frontend_i18n.py` | 生成新增界面文案，不手动维护重复目录 |

可按阶段新增 `prompt_diagnostics.py`、`visibility_rules.py`、`content_cards.py`、`shoot_plan.py` 等小模块；文件名为建议，不是当前已存在的文件。只在实际功能需要时抽取职责，不为本次方案进行大规模重写。

### 8.2 数据与兼容原则

- 现有 11 个节点的类型名、原有输入键和输出位置保持兼容，旧预设及 TXT 格式继续可用。
- 新参数的缺省语义、旧工作流迁移和新节点默认设置分别定义并验证。
- 执行所需状态作为实际节点输入参与缓存；不能仅保存在前端 properties、DOM 或全局变量中。
- 同一请求中的中英文、尺寸、诊断和计划引用同一份解析结果。
- 前端提交及结果展示支持无界面 API、缓存、排队和重开工作流，不依赖仅点按钮才能修正的隐藏状态。
- 内置元数据逐步使用稳定 ID；收藏、内容包及计划快照带版本，不把翻译后的显示文本用作唯一标识。
- 保持离线运行和现有 Python 依赖边界；自由文本不自动翻译，不为新增功能引入在线服务。
- 不默认给自由文本套上权重标签、否定描述或质量口号；空模块继续省略。

## 9. 验证与发布要求

每个工作项记录触发条件、实际变化和验收结果。运行与该项行为相关的回归；只有新增变更、失败或未解决问题需要时才扩大测试，不用无关重复测试替代实际验收。

发布前检查四个层面：

1. **逻辑**：同输入同结果、手动值优先、空模块保持空、中英文一致、无候选行为明确。
2. **界面**：中文／英文 × 经典／Nodes 2.0；弹层、隐藏字段、保存恢复和实际执行结果均可用。
3. **宿主执行**：纯文本图验证端口、旁路、缓存、API 请求与队列结果对应关系，不加载生图模型。
4. **交付**：干净发布文件集测试、生成目录一致、双语 README 与更新记录完整、安装包校验通过。

模型效果只在有对应图片及运行参数时标记为验证。若以后需要比较 Photoshoot 与本节点，固定模型、采样参数、画幅和测试种子，以构图遵循、动作可执行、服装一致、系列覆盖和表达差异逐项比较，不能只按提示词长短或候选数量宣称更优。

发布前检查是否复用了第三方代码或实质性资料；采用时保留适用版权与许可，并在相应文件及第三方说明中记录来源。示意图单独记录来源与使用条件。
