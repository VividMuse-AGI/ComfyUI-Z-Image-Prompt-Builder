## 3. 后续执行顺序

### R1：补齐经典界面及两个独立 TXT 节点（优先）

只用独立纯文本测试图。开始前核对服务代码及队列，记录语言和布局；结束恢复原设置和用户工作流。遇到未保存提示先保存测试图，不关闭保护或丢弃用户图。

1. 画面基础、人物、发型、服装、姿态动作、场景、摄影七个模块，各补中文／英文经典布局，共 14 个组合；检查状态入口、实际点击、文字刷新、紧凑高度及弹窗关闭，每组合执行一个代表输入。
2. 两个独立 TXT 节点各测中文／英文 × 经典／Nodes 2.0，共 8 个组合。实际导入示例，选择条目，检查手动与随机模式、实际种子／条目回显、缓存执行以及原有结果入口没有重复。
3. 每个 TXT 组合保存并在新文档恢复；核对条目、草稿、模式、种子、前置文本、连接与真实输出。固定种子应复现；换种子允许重复抽中，不能以“两次相同”直接判随机失效。
4. 确认没有保存诊断按钮／历史、字段移位或补入 null。手动模式与随机模式分别保留一份小型保存样本。

通过标准：字段／端口／输出不串位，按钮可用，语言切换不改变保存值，无重复控件或异常拉长。任何数据丢失、输出错配或无法恢复都阻断发布；先加定向回归再修，不进行猜测式旧图修复。

### R2：真实子图与连接输入边界

1. 当前宿主创建单实例子图，内放独立模块，执行及缓存执行，核对宿主实际返回路径与显示归属；再做嵌套路径和不同子图中的同编号节点。
2. 同一子图定义实例化两次，核对输出均正确，诊断按当前明示限制不合并到同一面板。若观察到宿主结构与实现假设不同，先记录再判断，不凭模拟路径宣称兼容。
3. 修改上游前置文本或摄影内容，下游暂不运行：详情仍标为上次结果，提示未预判上游变化；再运行，检查上下文及实际输出更新。断开／重连不应将休眠控件误计为随机项。

通过标准：绝不把结果写到错误实例，文字输出保持正确。不支持的诊断展示必须与中英文说明一致；共享定义限制不是输出故障，不能无依据扩大为“所有子图不支持”。

### R3：连续大文本与浏览器响应

已有 CPU 100 次结果和单次 200,004 字实机冒烟，不需从零重做。风险在重复正文占用，而非已确认内存泄漏：单条大文本诊断 UI JSON 约 1.81 MB，八模块长链合计约 8.05 MB。这些是序列化字节，不是堆内存。

1. 小文本基线、200,004 字自由文本、八模块长链三个样本，先各运行 10 次；确认队列和页面正常，再分批扩大至 100 次，不一次性淹没队列。
2. 记录第 1／5／10／50／100 次的响应、弹窗开关、记录数和可取得的内存指标；观察超过五条历史后的增长趋势。
3. 在测试图中移除／重建节点、切图后继续提交，观测已离开图的引用及大文本能否回收。代码中任务关联表虽限 128 条，但仍持有节点引用；数量有界不等于字节小或即时回收。
4. 自动化已覆盖超过 128 条淘汰；若实机出现持续增长，再用最小样本验证淘汰后的趋势。不能取得可信堆数据时明确标为未测，不能用 JSON 字节冒充内存。

通过标准：历史不超过五条，页面可操作，无持续恶化／异常或错配。先记录可重复基线再制定量化性能阈值；严重卡顿或不可回收的持续增长先复现后修复。不要仅为通过测试静默截断用户输出。

### R4：最低运行环境与宿主兼容

1. 在隔离环境用 Python 3.10／Node 22 运行公开测试及导入检查；不替换用户正在用的 Python、Torch 或宿主。
2. 在隔离 ComfyUI 0.31.1 验证注册、纯文本执行、保存恢复，以及首次执行／缓存命中时诊断行为，记录实际搭配的前端版本。
3. 区分“输出功能正常但旧宿主不回放缓存诊断”和“执行或保存失败”。前者需要清晰兼容说明及不误导的历史状态；后者必须修复或经用户同意调整支持声明，不能擅自提高最低版本。
4. 无可用环境时保留未验收项；经授权提交推送后使用真实 CI 补 Python／Node 结果，不把 CI 配置文件当作通过证据。宿主兼容仍需独立证明。

1. **撤销恢复尚未证实。** 明确删除／同 ID 导入通过，只证明重建隔离；不能替代 Ctrl+Z 恢复原字段。先前种子 16／15 没有删除前快照，不足以认定数据丢失，也不足以判通过。

| T3 | 最低运行时 | 隔离 Python 3.10／Node 22 跑公开范围测试、导入、生成一致性；不替换全局环境 | 当前相同快照预期 187 项 Python／21 组前端全部通过；新增测试则记录新计数。环境不可用时明确阻碍，实际 CI 需授权推送后补证 |
| T4 | 旧前端及缓存刷新 | 隔离 0.31.1 配套前端，记录准确版本；完整节点、摄影模块、两类 TXT，各测执行、缓存、保存重开，抽查中英文；当前前端补一次可证实绕缓存重载 | 保存值／输出正确、控件可用，实际加载脚本与候选源码一致。不要求旧前端提供其本身不支持的 Nodes 2.0；不得借验收升级正在使用的宿主 |
| T5 | 定向内存诊断 | 先验证有可靠堆快照能力；分别观察同图重复、大文本图删除／切换、关联项淘汰后的存活引用。区分宿主标签页／撤销／缓存与本扩展引用 | 有工具再做带基线的回收分析；关联数量及历史上限正确，淘汰后本扩展不再保留旧任务所有权。不以进程 RAM 或 JSON 长度替代堆；无工具明确未测，不无限重复百次测试 |
| T6 | 发布候选重新冻结 | 汇总上述结果，审核最终 diff；仅文档改动检查链接、范围、秘密模式、ZIP 及哈希，代码变化先定向再全量回归 | 版本、双语说明、变更日志一致；用户授权后才提交／推送、确认真实 CI、发布并从正式附件安装冒烟 |

T1／T2 是低成本优先项。T3／T4 用于兑现现有支持声明。T5 为容量风险补证，不将“没有堆工具”本身称为节点故障；若不能完成，明确残余风险和是否接受，不擅自宣称全部验收通过。

### 7.4 停止与发布判断

- 发现可复现的输出误归属、字段丢失、保存损坏、声明支持环境执行失败，或严重且持续恶化的页面问题，阻断发布：保留最小复现，补回归再修复。
- 同种子复现、换种子偶尔抽中相同条目、共享子图定义的已声明诊断限制，不重复登记为故障。
- 没有新失败／源码变化，不重跑已完整通过的 R1／R2 全矩阵，也不再重复百次提交来代替缺失的请求／内存证据。
- 所有实机用例仅使用我方独立纯文本图；不运行生图、不干扰用户队列、不丢弃未保存工作流，结束恢复语言、布局、批次和原工作流。
- 当前结论为：**可进入定向收尾测试，尚不宣称无条件正式发布就绪。** 此方案不自动授权提交、安装、升级运行环境或发布。
