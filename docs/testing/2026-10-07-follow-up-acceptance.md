实机环境：ComfyUI 0.39.0、前端 1.53.10、Python 3.11.9。旧宿主从本机已有 `v0.31.1` 标签导出到独立工作区，使用相同 Python／Torch，只测 CPU 执行器，没有启动第二个前端。干净公开范围回归使用 Python 3.12／Node 24，不把源目录中的研究测试混入交付计数。

## R3：百次级文本与生命周期

| 样本 | 实际证据 |
|---|---|
| 小文本完整节点 | 先逐次执行代表种子，再 10 批 × 10 次确认 100 个成功任务。每批读取十个 ID、序号、实际种子及输出长度，确认全是本项目纯文本 QA 图；终点输出 475 字、历史 5 条 |
| 200,004 字自由文本 | 初始 10 次及后续百次级 UI 提交；终点实际种子 100、输出 200,465 字，队列为空、正文保留、历史 5 条 |
| 200,004 字前置文本＋八模块 | 100 次主提交，终点输出 200,467 字；八个模块逐一打开详情，历史全部为 5 条。首模块实际种子 100，其余固定为 0，不是随机失效 |
| 删除／同编号重建 | 经典测试图明确删除摄影节点，再导入已知输入的同编号图；运行前无旧历史，运行后种子 0、路径 2、正文及连接正常 |

完整节点及长链没有开启字段随机，正文固定。改变种子可重新执行，但相同前置文本使下游包含缓存回放；**不是 100 次全字段随机或所有下游都未命中缓存的性能测试**。大文本／长链以 UI 提交序列、检查点与终点为证，没有像小文本一样保存全部 100 个服务 ID，不能混同计数证明强度。

第 1／5／10／50／100 个代表检查点可开关详情，记录增至 5 后维持上限。早期小文本打开并读取详情约 301–334 ms，长链终点约 381 ms，大文本第 50 次约 797 ms；包含自动化往返，样本有限，不是渲染耗时／P95 基准或性能承诺。

工具两次因整批执行超时重置，页面仍在、队列空闲、无前端 error，恢复后继续核对；不把中断脚本的内存变量当持久证据。一次终点快照先读到 97，等待提交及消息完成后读到 100。最后五条也可能都是 100：快速 Run 与编辑时，异步提交可读取后续值；面板应显示真实执行值。取消按钮短暂禁用不是提交完成证明，因此小文本最终用每批服务任务确认。

早期删除／撤销假定种子应恢复 16，实际为 15，但删除前未捕获序列化值，证据不足。原项保留为 **未定、由明确删除／导入重测替代**，不算通过或数据丢失。最终 UI 记录 48 项：47 项通过、1 项被替代的未定断言，不将其隐藏成“48 项全通过”。

没有取得浏览器堆、GC、旧图引用释放指标。系统总 RAM、序列化 JSON 字节不能替代堆数据。页面可用、历史有界不证明无泄漏；128 条关联仍可能持有旧节点引用。保留容量风险，不截断正文或猜测式改回收策略。

## R4：旧宿主及验收脚本修复

原两个脚本无条件给 PromptExecutor 传 `asset_manager`，旧宿主没有此参数而报 TypeError。现按真实构造函数签名传参；旧宿主不传，当前宿主仍传禁用管理对象。新增两项旧／当前签名回归覆盖两脚本，不改运行节点。

初次重跑卡在 Windows asyncio `socketpair/accept`；调用栈证明沙盒限制本机通信，尚未执行节点。只结束我方两个卡住的测试进程，允许测试所需本机通信后通过：

- 30 次 CPU 结构化执行：9 个节点，实际种子、隐藏 ID、诊断／文本一致、缓存、固定输出、自由文本与替代。
- 9 次 CPU TXT 执行：缓存、种子／词库／模式／模块变化及空候选处理。
- 未改变运行中的宿主、Python、Torch、xFormers。既有二进制版本警告不阻断纯文本，不修复无关 GPU 环境。

这不是 Python 3.10 或旧前端 UI／保存恢复证明。本机未找到 Python 3.10／Node 22，不安装新全局环境或提高最低版本；仍需隔离运行时或授权推送后的实际 CI。
