## 2. 冻结的新动作内容

| 内容 | 翻领 | 领口边缘 |
| --- | --- | --- |
| ID | `touch_foldover_collar` | `touch_neckline_edge` |
| 手部选项 | 一手轻扶翻领 | 一手轻扶领口边缘 |
| 精简／标准中文片段 | 一手轻扶翻领 | 一手轻扶领口边缘 |
| 详细中文片段 | 一只手轻扶衣服向外翻折的领片，另一只手自然垂落 | 一只手轻扶衣服领口的布料边缘，另一只手自然垂落 |
| 英文界面 | Hand lightly touching a fold-over collar | Hand lightly touching the neckline edge |
| 英文正文 | one hand lightly touching the folded-over collar of the garment, the other arm resting naturally at the side | one hand lightly touching the fabric edge of the neckline, the other arm resting naturally at the side |

两个 ID 在当前姿态词库中均未占用，两个中文标签不与现有选项重名。所有密度下，英文均保持该完整表达，不用模糊的 collar 替换 neckline。旧 `adjust_collar` 的中文、英文、ID 和随机资格保持不变。

这些是文本语义及渲染验收，不是模型图像识别能力的证明。手动选择精确动作仍需用户搭配有对应结构的衣服。

## 3. 七条服装结构证据

以下标注针对已有中文详细词条中的事实，而不是给任意服装或最终图片下结论。英文目前为简短服装名称，未完整重述中文结构细节；不能把中文的支持状态自动视为英文最终提示词也已明确输出该结构。

三列属性依次为“向外翻折的领片”“衣服领口布料边缘”“可供手插入的衣物口袋”。支持仅表示词条对结构存在提供依据，不保证位置可见、手可触及或动作成功。标注不进入运行时。

| 字段与稳定 ID | 现有中文详细词条 | 英文原子输出 | 翻领 | 领口边缘 | 可插手口袋 |
| --- | --- | --- | --- | --- | --- |
| `clothing.dress_type / shirt_dress` | 衬衫式连衣裙，翻领、门襟和腰带完整 | shirt dress | 支持 | 未知 | 未知 |
| `clothing.top_type / denim_jacket` | 短款牛仔外套，翻领、口袋和车线细节清楚 | denim jacket | 支持 | 未知 | 未知 |
| `clothing.dress_type / slip_dress` | 缎面吊带长裙，细肩带与垂坠裙摆完整可见 | slip dress | 未知 | 未知 | 未知 |
| `clothing.dress_type / halter_dress` | 挂脖连衣裙，肩颈与领口结构清楚 | halter dress | 未知 | 支持 | 未知 |
| `clothing.bottom_type / straight_jeans` | 高腰直筒牛仔裤，车线与口袋结构清楚 | straight jeans | 未知 | 未知 | 未知 |
| `clothing.bottom_type / cargo_pants` | 多口袋工装裤，裤型宽松挺括 | cargo pants | 未知 | 未知 | 未知 |
| `clothing.bottom_type / yoga_pants` | 高腰贴合的瑜伽裤 | yoga pants | 未知 | 未知 | 未知 |

21 个属性格中有 3 个中文结构支持、18 个未知、0 个明确排除。原因及使用约束如下：

- 衬衫裙与牛仔外套明确出现“翻领”；不由此推出领片尺寸、开合、身体位置或西装驳头语义。
- 挂脖连衣裙明确出现“领口结构”，支持领口存在；不推断具体边缘位置或可达性。
- 牛仔外套、牛仔裤与工装裤虽写了口袋，但没有明确其开口、位置及是否可伸手；“口袋存在”和“可供手插入”不是同一个属性。
- 吊带长裙、瑜伽裤未提供相关排除信息。下装自身没有描述领口，也不能推断整套穿搭没有领口；本表不做跨衣物推断。
- 连衣裙证据仅用于活动连衣裙分支，上装／下装证据仅用于各自活动分支。隐藏选项、叠穿中的其他衣物、TXT 替代、空值、普通文本前置不能用本表补全。
- 英文名称未复述细节时，面向英文输出的结构判断保持未知；本版不改旧英文、不借标注静默补词。

没有排除态不是数据错误，也不通过添写“无口袋”之类反向提示词补齐。

## 4. 随机入口与隔离清单

| 路径 | 当前依据 | 阶段二约束 |
| --- | --- | --- |
| 手动下拉 | `FIELD_OPTIONS`，完整／独立节点直接构造控件 | 在全部旧条目注册后末尾追加，不能只在原词库中提前插入 |
| 原子随机与回退 | `_choose_from_pool` 读取 `RANDOM_FIELD_OPTIONS` 或 `PROFILE_POOLS` | 不修改旧列表；新标签不得出现在任一基础随机来源 |
| 初始化复制 | `RANDOM_FIELD_OPTIONS` 从 `FIELD_OPTIONS` 复制 | 在复制之前添加新动作会造成泄漏风险；注册流程必须隔离 |
| 动作套组 | `POSE_BUNDLES`、预设／主题／专业套组及匹配回退 | 保持全部旧套组，不能新增含新动作的套组 |
| 引用扩展 | `REFERENCE_POOL` 在初始化时追加公开选项，并使用自身条目及条件抽样 | 不在引用条目中添加新动作；新手动值应排在全部旧公开值之后 |
| 协调替换 | 已记录的真实动作候选池与独立随机流 | 保持候选数据，固定新手部值仍受保护，不新增协调规则 |
| 完整节点随机按钮 | `prepareRandomCombination` 设置随机占位值与种子，尊重模块／锁定范围 | 不是从下拉抽具体词；保持现有逻辑 |
| 独立模块随机按钮 | `prepareModuleRandomCombination` 设置随机占位值与种子，尊重锁定 | 同上，不增加“新动作永久锁定” |
| 搜索与收藏 | 目录生成遍历公开选项，搜索模块不提供内置随机抽样 | 应可检索新值；有搜索结果不表示进入随机池 |
| TXT 随机抽取 | 从用户导入条目选择，独立于内置动作池 | 保持现有行为，不禁止用户自主提供新动作文字 |

夹具验证采用“旧池和旧公开条目全部初始化完成后，集中注册两个手动值”的方式。字典注册同时包含中文渲染、英文原子映射与稳定 ID；英文界面短标签通过独立显示覆盖处理。搜索目录、姿态卡候选均读取公共注册值。

这证明该最小方案在当前入口可行，但不是对未实施代码的全路径保证。阶段二须以实际注册位置重新核对随机可达性、别名字典、加载顺序及生成目录，并补真实链路和卡片验证。

## 5. 允许变化与实施边界

预计需要修改的范围：

- `nodes.py`：集中手动条目注册、稳定 ID、中文详细表达及英文输出映射；不得修改旧随机来源和协调算法。
- `scripts/generate_frontend_i18n.py`：两个英文界面短标签及必要说明；保持旧标签。
- `web/js/i18n_catalog.js`、`web/js/library_catalog.js`：由现有生成器再生，差异限于新内容和获准说明。
- 定向测试与中英文使用说明；服装结构证据只留开发文档。

若实际实现选择现有词库作为源，必须同样保证末尾追加与随机隔离，并列明额外源文件差异；不能复制一份数据后留下不一致的双重来源。当前优先采用集中手动注册，避免为两个条目新增无使用方的格式。

不修改 `combination_coherence.py` 的规则，不改变引用扩展池、预设、版本号、用户数据或生产安装。前端卡片／搜索逻辑若无实际兼容问题，不顺带重构。
