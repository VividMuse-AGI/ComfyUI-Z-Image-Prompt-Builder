# v0.10.0 Acceptance / 验收记录

## Scope

Person and outfit cards, scoped application and module-lock shortcuts. Existing field locks, node inputs, backend randomness, ports and node count are retained. No images were generated.

## Automated verification

The clean public development copy passed 195 Python tests, 23 frontend suites, 15 JavaScript syntax checks and three generated-catalog comparisons using Python 3.10.11 and Node.js 22.20.0 on Windows. Private local test tools are excluded from these counts. Final staged-copy checks are repeated before commit; GitHub release CI repeats the public suite on Ubuntu before publication.

- Actual Python schemas, all built-in presets, complete/standalone card round trips, all required fields, invalid type/value/category rejection and zero mutation on validation failure.
- Scoped application preserves other modules, free text, settings and execution history. Cards are copied on save; 100-card limit and replacement paths are exercised.
- Linked inputs and TXT replacements reject capture/application/new locks. Unlocking remains available.
- Full-builder and standalone random buttons preserve locked selections. Actual Python parsing and bilingual standalone output are stable across three distinct seeds for the captured person/outfit fields.
- Simulated DOM events cover default card scope, Escape/IME composition, import size, and late asynchronous imports after closing. These simulations do not replace native OS interaction checks.
- Existing serialization, layout, translation, randomization, TXT, resolution and framing regressions remain included.

- After handoff, the user confirmed no problems with the requested operation experience, actual export/import and physical Chinese input method checks. These are user-reported passes, not a new automated download-file inspection.

## Boundaries

Person cards include makeup and physique, not hair. Cards freeze descriptions, not face identity. Random fields must be made concrete before capture/locking; execution-history restoration and batch series generation are not included. Card JSON is distinct from result snapshots and workflows. Manual edits, preset changes and clearing are intentionally not blocked by random locks.

Representative testing does not imply exhaustive host-version coverage. Release CI and asset checks are reported against the v0.10.0 tag; no private paths, workflows or audit fixtures belong in the public package.

The final 147-file public snapshot passed targeted token, private-key and private-path checks with no findings. Catalog comparisons normalize Windows/Linux line endings only. Internal plans, backups and private test tools were excluded; these targeted scans are not a guarantee against all possible secret formats.
