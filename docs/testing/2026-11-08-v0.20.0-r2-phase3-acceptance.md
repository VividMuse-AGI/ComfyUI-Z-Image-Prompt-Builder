## 复制反馈及核实

浏览器工具最初读取虚拟剪贴板为空，粘贴操作报告没有数据，因此请求人工在记事本补验。用户反馈“复制中文，实际复制到的是英文”。

核对实际提供的源码和结果数据后，两个按钮分别调用 `copy("zh")` 与 `copy("en")`，导出文件中的语言也未互换。既有复制及历史选择定向测试通过。

随后在用户正在查看的独立姿态结果面板中，单独点击“复制中文”，浏览器剪贴板读取到完整中文。再按“复制英文→复制中文”顺序逐次读取，分别得到正确英文和中文，证据记录于 `clipboard-check.json`。目前不能认定为节点语言绑定错误，也不能据此否定用户观察；外部系统剪贴板同步、旧内容残留等原因尚未确定。已请求用户直接粘贴最后一次中文复制结果，等待确认。

用户随后确认：代理最后一次点击“复制中文”后，在外部仍粘贴出英文或旧内容。因此浏览器工具读取的剪贴板不能作为系统剪贴板已更新的证据，复制验收继续保持未通过。已进一步请求用户亲自单击“复制中文”后立即粘贴，并注明侧边栏或普通浏览器，以区分代理点击与真实用户点击路径；尚不能确定根因。

复查未发现另一处结果复制处理器改写语言，定向 `frontend_prompt_diagnostics.mjs` 测试再次通过（包含中文、英文、历史记录选择及权限失败提示）。截至这一轮核实尚未修改产品源码，不能将上述检查称为已修复复制故障。

### 用户手动点击仍失败后的补救

用户进一步反馈“没有复制到内容”。当前不能确认具体浏览器环境的根因，也不把虚拟剪贴板测试作为系统复制通过的依据。本轮修改仅涉及结果面板：

- 增加“手动复制中文／英文”，显示只读文本框并全选对应历史结果；用户可直接按 Ctrl+C／⌘C，避开异步剪贴板接口。选择本身不声称完成复制。
- 原复制接口报错或不可用时，自动显示并全选对应正文；原接口成功时提示具体语言及备用入口，不再笼统声称系统复制完成。
- 迟到的异步复制回调不得覆盖后续手动选择或切换执行记录后的状态。

开发目录及 8202 独立副本同步了 `web/js/prompt_diagnostics.js` 与 `tests/frontend_prompt_diagnostics.mjs`，未更新生产安装。更新前清单保留为 `manifest-before-copy-fallback.json`。

验证结果：本次枚举并执行的 36 个 `frontend_*.mjs` 脚本全部通过；`git diff --check` 通过。真实 Nodes 2.0 中文界面重新执行独立姿态工作流后，手动中文选中范围为 0–38（全部 38 字符），手动英文为 0–123（全部 123 字符），只读文本框取得焦点且内容与结果一致。用户随后回复“这次能复制成功”，确认手动复制中文的系统粘贴路径可用。英文系统粘贴未单独获得人工确认；原一键复制失败的根因仍未确定。

### 一键复制根因隔离与最终复验

此前“未定位”的结论在本次对照后更新。Windows 剪贴板通过权限批准后的 `Get-Clipboard -Raw` 只读核对，仅返回与测试文本是否完全相同，不输出或保存其他剪贴板内容。沙盒内相同命令曾返回空值，而权限批准后的读取非空，因此沙盒读取不作为系统剪贴板证据。

最小测试页面不加载 ComfyUI 或节点 JS：

1. 全新标签页原生点击复制标记 D，Windows 内容为 D；另一个全新标签页使用 Playwright 点击复制 E，Windows 内容为 E。因此不能把问题归因于 Playwright 点击本身。
2. 在前述 D 标签页调用浏览器会话 `tab.clipboard.readText()` 后，再点相同按钮，接口仍成功、点击可信且文档有焦点和用户激活，但 Windows 仍为 E；会话剪贴板则变成 D。
3. 原受影响的节点页面同样表现为会话内容更新、系统保留旧文本。该现象不依赖节点代码，黑盒定位到当前验收会话的剪贴板工具介入。
4. 新建干净 ComfyUI 标签页，不调用任何 `tab.clipboard` 方法，运行纯文本节点后分别点击原一键复制英文、中文，两次 Windows 剪贴板都与对应实际正文完全一致。

结论：本次故障来自验收工具启用的虚拟剪贴板路径，不是中英文按钮绑定或节点正文取值错误。没有修改浏览器内部实现，也不推广为所有版本、所有环境的行为保证。后续系统复制验收应使用未受该工具影响的标签页，通过系统只读匹配或人工粘贴验证；不要用会话剪贴板读数替代系统证据。已关闭本轮受影响的代理测试标签页，保留正常的新页面。

本轮诊断没有继续修改产品代码。先前加入的手动复制入口目前保留为备用功能，不能把它描述成修复虚拟剪贴板根因的代码。
